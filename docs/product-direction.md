# 来信绘本：本轮目标与验收边界

2026-11-02 用户确认：允许大幅重构，先验证一个完整跨页，再推广五章。

## 成品目标

朋友打开一个链接，看到一本属于这封来信的插画书；能自然打开、读懂真实笔迹、翻阅五章，感受到原画角色的陪伴。真实来信是阅读主线，插画负责叙事情绪，书本动作服务阅读。

## 第一阶段：HELLO 可翻动样章

- 以 `fded90c` 为同条件基线，原分支保留，不直接合并发布。
- 重排首章：真实原迹有独立阅读空间，大幅英文标题不再压过来信；原兔子、狐狸及分层场景仍在纸上活动。
- 手机保持装订双页全貌，同时能在同一本书里放大左页/右页；不把另外一份信件图片列表当主要阅读界面。
- 保留原笔画与已获准公开的素材，不生成替代笔迹，不公开源视频或完整源帧。
- 保留唯一 Book 渲染器、柔性半页、封面、双向翻页和减少动态支持。生日定制功能不受损。

## 可证伪的假设

给笔迹留出安静的纸面、降低巨型英文标题的竞争，并让手机放大实际书页，能改善纸条覆盖感与阅读分离；不需要先替换曲页算法。

若真实截图仍显示笔迹像附件、放大不能清楚读信、角色被遮住或翻页中排版跳变，则本轮须继续迭代，不能以 CI 通过判定成功。

## 验收

桌面 1440×900、手机 390×844；相同首章、相同原画与静止动作；封面和 HELLO→GROW 的 0/25/50/75/100% 姿态。记录真实开书、前翻、回翻、手机左右页阅读与还原录像。检查字迹不镜像、阅读焦点不错误触发翻页、页面不溢出；保持原有键盘、拖动取消和 reduced-motion 检查。

先由实际效果决定 keep / iterate / reject，再推广剩余四章。真机 Safari、最终视觉确认与上线是后续验收，不以模拟器代替。

## 防止再次跑偏

本阶段只做首章内容编排和直接相关的阅读交互/渲染修复。不开新产品模式，不另建引擎，不增加逐文件哈希发布关卡，不把历史实验全合入 main。代码行数不是保留理由；新实现应替换对应旧路径，历史靠 Git 保存。
