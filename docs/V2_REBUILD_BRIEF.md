# Storybook V2 — 产品重启与验收合同（2026-10-30）

**状态：已启动的实验性 V2；不是已验收的发布版本。** 当前公开的 \`main\` / GitHub Pages 仅作可回退 V1 基线；V2 未经用户视觉签收不得自动发布。V2 的具体实现、设计和渲染算法均可推翻，不以保护旧代码为目标。

## 1. 唯一的产品目标

做一份**可以发送给一位重要朋友的、真正愿意慢慢翻完的生日绘本**。打开时是一本有厚度的竖版精装封面；打开后是两个围绕中央书脊装订的真实页面；只翻动一张半宽右页或左页，而不是把整张横向卡片旋转。五章 HELLO → GROW → TOGETHER → DREAM → WISH，祝福可自定义，链接可以跨设备分享。

情绪关键词：**手作、温暖、带一点夜色的魔法感、克制、亲密，而不是技术演示、PPT或卡片轮播。**

原始参考：用户给出的 30 秒录屏 \`1.mp4\`（只在用户资料里；不上传公共仓库），来自 Hello Monday 的 editorial interactive flipbook。借鉴**每章独立的叙事构图、巨大且与场景共生的标题、角色表演、动态景深和节奏**；**不复制版权素材、不复制整个画面的卡片旋转结构**。

最初提供的生日绘本概念展板属于**美术风格目标，不是完成资产或逐像素蓝图**。两份资料一起定义“视觉标准”，但用户最后的实际屏幕体验拥有最终否决权。

## 2. V1 失败复盘（已经观测，不以 CI 绿灯抵消）

- **构图**：界面较像展陈型产品，章节重复使用相似图层、角色和排版；没有参考视频“一章一张独立海报”的视觉冲击。
- **手机**：旧版在 390×844 截图里画面很小、页内字体小，按钮触控列仅 24px；移动页面主要是缩小桌面，而不是为手机重新排布。PR #27 首次零列网格尝试还曾让整本书隐藏，证明需要真实布局门槛。
- **物理翻页**：分段 CSS 纸张满足数值几何和多数像素测试，但视觉上仍会出现折线、压缩、突然变形、速度不自然等风险。真实 iPhone Safari 的帧率、内存、闪屏尚未验证。
- **美术**：6 张同尺寸 SVG 图层不等于合格的层次感。精细角色动作、光影、标题、场景一致性缺少人工验收。
- **产品定义**：“部署成功 + 浏览器自动测试全过”被误称为“接近完成”。V2 的完成条件必须包含用户亲眼认可。

## 3. 保留、重写、删除原则

| 组件 | 决策 | 条件 |
|---|---|---|
| 五章数据与故事顺序 | 暂保留 | 文案、章节镜头可以重写 |
| \`#gift=\` 分享编码、表单 | 保留可用协议 | 兼容旧分享 URL；不能把私人祝福写到服务器 |
| 原 SVG 图层、角色、封面 | 仅作为 V1 对照素材 | 允许全部重画；不要求沿用旧笔触和排版 |
| 书本排版与响应式布局 | **重写** | iPhone 先设计，不是缩放桌面 |
| 当前 GSAP / CSS 分段弯曲 | **不保留特权** | 对照简单平整翻页、改进分段、WebGL 网格；若中段不自然或 Safari 卡顿就替换 |
| \`main\` 线上网址 | **保护** | 单独分支 + 真实截图录像通过 + 用户确认后合并 |
| 旧 PR #27 | 保持历史，不合并 | 被 V2 重新设计取代，无需把临时 CSS 强行合入 |

## 新增核心需求：捏住纸张的双向直操翻页（2026-10-30）

**这一条不是可选增强，是产品必须具备的交互。** 鼠标左键或手机单指按住当前书页，纸张从书脊弯曲，随拖动实时正向/反向移动；不松开时允许反复回拉，不得按旧的 1.28 秒动画自动翻完。松手时才根据当下的位置决定翻到下一页/上一页，还是回弹原页。前进抓右页，后退抓左页，封面也必须遵循相同装订边逻辑。左右箭头、键盘作为可访问的备用操作。

**技术验证门槛：** (a) 真实鼠标拖过中线，停留 1.5 秒仍能拿住纸；(b) 拖过 70% 后拉回 10%，松手取消；(c) 松手超过中线才提交，倒向拖动可返回；(d) 390×844 单指 pointer 交互不触发旧 swipe 的二次翻页；(e) 贴图在手指下不卡住、无折裂，无贴面穿透；(f) iPhone Safari 实测无取消指针/滚动冲突，逐帧验收。**自动化通过只证明事件语义，不能证明真实纸感。**

**第一轮可执行原型：** 已将手势绑定到现有分段纸页的 0～1 `posePaper`，允许前后拖动、松手回弹。它并非最终纸张模型，若触摸跟手延迟或连续形变不自然，必须重构贴图/曲面/渲染，不可直接签收。

## 4. 三个可否决的交付关卡

### G1：美术和手机“样板”关（当前阶段）
只有**封面、HELLO、GROW**。要求在 390×844、393×852 DPR 3、1440×900 三个视口呈现；书本保持单一中央书脊；手机主要操作按钮至少 44×44 CSS px、无遮挡、不发生横向溢出、重要文字可读。**同时输出实际截图和连续打开→翻页→返回录像**。重点由用户对照原版视频判定：标题、插画、叙事和材质是否值得继续。首轮只提供新的封面艺术和移动排版骨架，**尚不满足 G1**。

### G2：纸张引擎关（从 G1 反馈选择方向）
制作同一份 HELLO/GROW 艺术的匹配对照：A 当前分段曲纸、B 简化可读翻页、C 真实网格/着色器（如果必要）。同环境同时间轴检查 0/25/50/75/100%，前进和后退、文字非镜像、落页无闪屏、页背不会露底。测量帧耗时和真机 Safari；**最优方案不必保留现有引擎**。不要为了曲率指标牺牲可读性、帧率和整体感觉。

### G3：完整五章交付关
统一但非同质的五章画面；不同章节有不同角色动作与主色；个性化中英文/中文排版不溢出；封面、页数、键盘、触屏、减少动态、URL 分享完整。必须有**Chromium / WebKit 自动化 + iPhone Safari 真人观看的连续视频 + 用户审美认可**三层证据。测试通过≠用户认可。

## 5. 执行路线（先原型，后选择技术）

1. **先做真实画面**：独立 \`rebuild/editorial-book-v2-20261030\`，用独立原创封面插画、桌面舞台、手机体验和新增布局测试示范 V2 的代码方向；不得影响 V1 网址。
2. **重画 HELLO**：构图先行，标题与角色插画一起完成；建立对照视频、裁切/文字验证。
3. **重画 GROW**：用完全不同的情绪和构图验证是否真的有章节多样性，避免复制 HELLO 换配色。
4. **决定翻页技术**：用两章做真实前后翻测试，必要时整个替换 \`Book.tsx\` 及 \`paperGeometry.ts\`。
5. **推广三章、试分享、真机复核**，再申请用户确认上线。

## 6. 责任与禁止事项

- AI 完成构图、代码、画面、测试和录屏的可复查版本；用户只需要指出最差的画面/体验并决定方向，不必帮 AI 找 CSS 原因。
- 不可把用户未见过的“概念图”、CI 数字、单帧截图称为最终效果；不得在没有真实设备证据时声称 iPhone GPU 性能合格。
- 不做付费后台、账号、商店。不要复制参考站素材。暂不折腾 AWS。
- 所有阶段以 GitHub issue、PR、证据链接留下记录；Notion 同步只有在按现行 Registry + Write Protocol 找到明确 canonical 后才允许写入。
